Apple Container: Apple's free, light way to run Linux apps on a Mac

Apple's own free tool for running Linux containers as tiny virtual machines on Apple silicon Macs.

DevelopersStudents

stars: 51K · license: Apache-2.0 · platforms: Mac with Apple silicon

The problem it solves

A lot of modern software is shipped in "containers." A container is like a sealed lunchbox for an app. It holds the app and everything the app needs, so it runs the same way on any computer.

The catch: most containers are built for Linux, not macOS. To run them on a Mac, people usually install a big extra app that runs in the background all day. Those apps can feel heavy, use a lot of memory, and slow down a laptop.

What it is

Container is a free, open-source tool made by Apple. It lets you create and run Linux containers on your Mac. Each container runs inside its own tiny virtual machine (a small, pretend computer inside your real one).

It is written in Swift, Apple's own programming language, and it is tuned for Apple silicon chips, like the M-series chips in newer Macs.

It works with standard container images (the "lunchbox" files). You can pull images from any normal container library, run them, build your own, and push them back up. Images you build also work in other standard container tools.

Who it's for

  • Software developers on a Mac who test apps in Linux containers every day.
  • Computer science students learning how servers and containers work.
  • Data and AI hobbyists who want to try open-source tools that ship as containers.
  • IT staff and tinkerers who want an Apple-made option instead of a third-party app.

Be honest with yourself: this is a command-line tool. You type commands into Terminal. There is no point-and-click window. If you have never used Terminal, this is a fine first project, but expect to learn a few commands.

What you can do with it

  • Run Linux containers on your Mac, each in a light virtual machine.
  • Use standard images from any container library, such as small Linux systems or web servers.
  • Build your own images and publish them to a container library.
  • Run images elsewhere. What you build works with other standard container apps.
  • Install with a signed package from Apple, then start it with one command.
  • Upgrade, downgrade or uninstall with included scripts, and choose to keep or delete your data.
  • Follow a guided tour. The project includes a tutorial that walks you through building, running and publishing a simple web server.

How to start, step by step

First you need: a Mac with Apple silicon, running macOS 26. Older versions of macOS are not supported.

  1. Go to the project's Releases page on GitHub and download the latest signed installer package.
  2. Double-click the package and follow the steps. Enter your Mac password when asked. This lets it place files in a system folder.
  3. Open Terminal and start the background service:
container system start
  1. Run your first container to test it:
container run --rm alpine echo hello

This downloads a tiny Linux system called Alpine, runs it in a small virtual machine, prints "hello," and cleans up when done.

  1. When you want more, open the "start here" tutorial linked in the README.

To remove it later, the README lists an uninstall script. Use the -k option to keep your data, or -d to delete it.

Good to know

  • Apple silicon and macOS 26 only. Intel Macs and older macOS versions will not work. The team says it typically will not fix issues it cannot reproduce on macOS 26.
  • Still being built. The README says the project is under active development. Some features are marked "experimental" and may change.
  • Upgrades need a stop first. Before you upgrade or downgrade, stop it with container system stop.
  • Free, no paid services. The tool itself costs nothing. You only download images, which are usually free too.
  • License. It uses Apache-2.0. In plain words: you can use it, change it, and even use it in paid products, as long as you keep the copyright and license notices.
  • Not a full replacement for everything. It runs containers, but if your team relies on specific features of another container app, check the command reference before switching.

The bottom line

Container is Apple's own free tool for running Linux apps in sealed boxes on a Mac, built for Apple silicon. If you are a developer or student on a newer Mac, it is a light, official option worth trying. Just know it needs macOS 26 and some comfort with Terminal.

Get it: github.com/apple/container
